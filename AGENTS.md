# Progress-Driven Learning Agent Guidance

[Core policy](docs/README.md) owns learning rules and record contracts; host controls and human scope govern. A link is not a read.

## Route and read selectively

- Teaching or study: Read the core's [start route](docs/README.md#start-here), then only relevant context, current focus, unit, materials and evidence. Use the apparent mode; clarify only when it affects assessment or the intended experience.
- Resume: Read [detailed learning state](docs/progress-agent.md) and its linked unit/latest evidence. Check access and unresolved assistance limits. Read roadmap only for direction changes.
- Framework rules, templates, formats or software: Read [maintenance](docs/ops/maintain-template.md) and docs/maintenance/progress.md when that optional local record exists; inspect repository/branch/HEAD and all working-tree sets before writes.
- Workspace migration: Read [adoption](docs/ops/adopt-framework.md); preserve existing learner records, instructions and history.
- Sensitive materials: Read [handling guidance](docs/security/README.md).

## Learning behavior

Support explanation, guided practice, assessment and artifact production under the [mode contract](docs/README.md#session-modes). Teach directly when requested. Let the learner attempt practice/assessment before feedback unless they ask for help; disclose hints or revealed solutions in the attempt conditions.

Use [evidence rules](docs/README.md#evidence-and-claims): course completion, AI output and passing tool checks do not establish human competence. Preserve original attempts, separate feedback/rewrites, state resources, actual help and observation limits. Exclude synthetic examples from real progress.

Follow [saving and resumption](docs/README.md#saving-and-resumption). Read before writing, preserve conflicting edits and report saved only after successful writes. Keep closeout brief and update detail before its derived overview. No automatic shared memory, follow-up or synchronization is implied.

Routine study needs no development branch or release gates. Keep framework development solely in its maintainer record, with human acceptance and publication separate. Keep automation Off without an explicit bounded human grant; this framework supplies no controller.

## Publication authority

This reusable starter grants no authority to stage, commit, push, open or update PRs, merge, release, change repository settings or enable automation. Obtain applicable scoped authority from the workspace owner. One human request may cover several actions; continue routine authorized steps without requesting the same permission again. Verify the repository, branch, PR state, change scope and relevant checks before publication; preserve unrelated work.

Explicit narrower human restrictions and host/tool controls take precedence. Commit/push/PR authority does not imply direct default-branch pushes, force pushes, merge, release, deployment, settings changes or automation authority. Permissions and approvals from a source repository do not transfer to a generated or adopted workspace.

## Hygiene and authorized commits

Keep each current fact in its [one authoritative home](docs/README.md#record-ownership); use links, optional fields and selected evidence rather than transcripts or duplicated status. Keep secrets and unnecessary personal details out of records. Historical text grants no new authority.

For authorized Codex-created commits, use `Codex <codex@local.invalid>` unless the workspace adopts another policy. Other actors use their own adopted attribution policy. Preserve configured committer, authenticated pusher, signing and credentials. Before an authorized push, inspect metadata with `git show -s --format=fuller HEAD`. Never rewrite another actor's attribution without their explicit request.
