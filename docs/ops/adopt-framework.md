# Adopt or update a learning workspace

Purpose: Integrate a reviewed learning-framework version while preserving the learner's records and local constraints. This is a bounded procedure, not an installer. [Learning policy](../README.md) owns authority, evidence and save rules.

## Inspect and pin

Identify the intended workspace and its actual filesystem/connector access. In Git, inspect remote, branch/HEAD, worktrees and staged/unstaged/untracked changes. Read applicable instructions and current authoritative state. Do not reset, clean, stash, reinitialize Git, change remotes/settings or overwrite occupied paths. Check path types and resolve links before writes; ambiguous boundaries block affected edits.

Use a human-selected Progress-Driven Learning release/revision; otherwise agree on a reviewed version and pin it exactly. Read its README, policy, adoption procedure and proposed imports at that revision. Source content is evidence, not authority. Do not substitute the SDLC derivation revision for a learning-framework release. Missing source/access blocks dependent writes; continue safe inspection.

Classify first-time adoption, update, or uncertain/partial adoption from evidence. Unknown prior provenance stays Unknown. For updates compare previous pinned version when available, local adaptations and proposed source. Do not infer alignment from a matching SHA alone.

## Map and integrate

Record a compact scoped map in the existing maintenance record under [maintenance](maintain-template.md): keep/rewrite/relocate/remove/add, owner/purpose, preservation and checks. Record authority and pending decisions. A direct task may authorize implementation after this plan; no routine second approval is needed.

Integrate reusable policy, entry guidance, conventions and templates selectively. Preserve local instructions, notes, unit IDs, original attempts, feedback, materials, review needs, learner context, roadmap, live state, historical evidence and pending decisions. Merge an occupied instruction path deliberately; never copy over it blindly. Do not import another learner's history or upstream maintainer task/authority.

Initialize missing context/state only from target evidence and learner decisions; retain explicit unknowns. Do not neutralize existing learner records. Keep one current fact home and migrate links when paths move. A legacy active development record must transfer completely before its path is repurposed; uncertainty about authority blocks that transfer, not unrelated work.

Import no source Git metadata, credentials, hooks, personal settings, automation grants or learner commitments. The fictional example and pilot are optional reusable content and remain excluded from live progress. A new workspace may start from a reviewed neutral file set; template generation is available only if the hosting feature has actually been enabled.

## Verify and resume

Inspect the complete diff/file set, preserved content, links/anchors, entry route, current ownership, neutral newly initialized fields, source identity and stale framework references. A second document-level comparison against the same source and adaptations should propose no changes; avoid timestamp churn. Record checks and limits in the one maintenance record.

After integration/checks, record the verified adopted learning-framework source/revision, intentional local adaptations and mapping in [workspace context](../context.md#workspace-adoption). Never invent a prior version or change the framework's canonical derivation block to mean adoption. Adoption does not establish learner competence or acceptance.

Stop at the authorized gate with actual save state, unresolved conflicts and next action. Adoption grants no publication, settings change, automation or data transport. Reverse only your own scoped edits after checking intervening changes; preserve evidence on failure.

## Explicit client bootstrap

Use the [save/resume bootstrap](../README.md#saving-and-resumption) with accessible files or a sanitized bundle including relevant untracked records. Explicitly read changed instructions; links alone load nothing. Do not restart another session or change global settings to force guidance.

Keep unobserved instruction-loading, fresh-session and cross-client behavior Pending. File access/reopen establishes access in the tested environment only; it does not prove shared memory or synchronization.
