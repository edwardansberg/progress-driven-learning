## Synthetic business request

> We need an internal app for staff to request shared laptops, screens and meeting kits. People should see what is available, and managers should approve expensive requests. Urgent requests should go first. Notify people when a request changes. Admins need to manage stock, and we need a simple report. Make it ready for next quarter.

No further business rules are confirmed. Ambiguity is intentional. Do not treat a plausible invention as a stakeholder decision.

## Initial attempt

1. Choose explanation, guided practice or assessment; artifact production can prepare a worksheet. In practice/assessment, let the learner attempt before feedback unless help is requested. Agree on the rubric below and permitted resources before assessment.
2. From the request, identify important ambiguities and prioritized clarification questions. Explain which answers affect scope or acceptance outcomes.
3. Draft a small set of requirements and testable acceptance criteria for one useful slice. State assumptions separately, identify actor/preconditions/action/observable result where useful, and include a failure or boundary case.
4. Explain how the criteria relate to the request, what remains undecided and what cannot yet be accepted. Do not attempt an entire application specification.
5. Save the original response and actual help conditions using the [future save scaffold](SESSION_TEMPLATE.md), then assess separately.

The synthetic requester supplies no authoritative answers through this file. If the agent proposes assumed answers for practice, label them and agree on their use before evaluating dependent criteria.

## Formative rubric

Use Meets / Partial / Not yet demonstrated with concrete findings against the response; no percentage or global mastery label.

- Ambiguity: Finds consequential uncertainty and separates questions from confirmed facts/assumptions.
- Requirement clarity: Names an actor, need and bounded outcome in language that can be reviewed.
- Testability: Criteria have observable pass/fail outcomes under explicit conditions, with a relevant failure/boundary case.
- Justification/traceability: Explains why each selected criterion matters and how it follows from the request or a labeled assumption.
- Limits: Identifies unanswered decisions and prevents them from becoming invented approval or unsupported acceptance.

An agent reviews text against these criteria; it cannot supply stakeholder authority, certification or employer recognition.

## Explanation, hints, feedback and revision

Explanation: Teach requirements versus acceptance criteria directly, using a separate small example when possible. Provide a full solution if requested.

Guided practice: Wait for the initial attempt, then give a targeted hint proportional to the gap. Record each material hint or solution exposure. Avoid silently rewriting the learner's response.

Assessment: Agree on resources and criteria, wait for the answer, then give criterion-based findings with limits. If the learner requests the full solution, provide it, record the assistance/mode change and treat the attempt accordingly; independence requires a later different task.

Feedback: Save assessor/source, rubric findings, limitations and suggested next practice separately. A learner revision gets a new labeled record linked to its original; an AI rewrite is explicitly agent-generated.

There is no model answer in this initial task file. Save any later worked solution in separate feedback/materials. File separation cannot prevent access to solutions or undisclosed outside assistance; this is not secure examination software.

## Fresh task and delayed review

After feedback, generate a different unexposed business request of similar difficulty, for example a contractor onboarding approval request with different actors/rules. Do not reuse the equipment task, the worked room-reservation example or a task whose solution the learner has seen.

Before the later attempt, agree on criteria and allowed resources, record actual help and identify whether conditions were observed or learner-reported. Reassess the capability from that new evidence without rewriting earlier findings. Record “independent” only with those conditions and limits.

Choose a later review date or practical trigger with the learner and record it in detailed state's small queue, with rationale in the unit. No fixed interval is prescribed and no reminder is installed. A later weak result changes the current unit assessment and practice need while prior attempts remain intact.
